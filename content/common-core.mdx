# The Common Core

The **Common Core** is the main curriculum of 42, which every student follows after a successful [Piscine](/wiki/piscine). It is a sequence of projects, organised in **circles**, that takes you from rewriting standard C functions to building a complete web application.

> [!NOTE]
>
> The list of projects and the deadline rules change over time and can differ between campuses. Your project tree on the intra is always the reference.

## Circles and projects

Projects are grouped in circles. You unlock the next circle by validating the projects of the current one. Along the way, you typically meet:

| Topic                     | Example projects                                    |
| ------------------------- | --------------------------------------------------- |
| C fundamentals            | Libft, ft_printf, get_next_line                     |
| System administration     | Born2beroot, Inception                              |
| Algorithms                | push_swap                                           |
| Graphics                  | so_long, FdF, fract-ol, cub3D, miniRT               |
| Unix and processes        | minitalk, pipex, minishell                          |
| Concurrency               | Philosophers                                        |
| Networking                | NetPractice, ft_irc, webserv                        |
| Object-oriented C++       | CPP modules                                         |
| Web and team project      | ft_transcendence                                    |

Some projects let you choose between options, and some are done in a team.

## Submitting and validating a project

1. **Register** for the project on the intra and its Git repository is created.
2. **Work** on it, pushing your code to the repository.
3. **Close** the project when you are ready, and book **peer evaluations](/wiki/glossary#peer-evaluation).
4. **Get evaluated.** Other students review your code with you, following an evaluation sheet. Some projects are also tested by the Moulinette.
5. **Get your grade.** A passing grade validates the project and gives you experience; bonus parts can push the grade above 100.

If you fail, you can retry the project, sometimes after a waiting period.

## Evaluation points

Asking for an evaluation costs **evaluation points**, and you earn them by evaluating other students. This keeps the system balanced: everyone evaluates as much as they are evaluated. Being a careful, honest evaluator is part of your training. See [peer evaluation](/wiki/glossary#peer-evaluation).

## Exams

Exams test what you can do alone, without internet or notes. You progress through **exam ranks** that are required to move forward in the Common Core. They run in the same locked-down environment as in the Piscine.

## Keeping your pace

42 has no fixed school year, but it expects you to keep progressing. Campuses use a deadline system, historically called the **black hole**: a countdown that grows when you validate projects. If it reaches zero, you lose access to the curriculum. Some campuses now use **milestones** instead.

## Advice

- **Understand, don't just pass.** Later projects build on earlier ones: a shaky Libft makes everything after it harder.
- **Evaluate seriously.** Read the code, test it and ask questions. You learn as much evaluating as being evaluated.
- **Use your peers.** Someone on campus has already struggled with the bug you have.
- **Keep your Libft.** Many later projects let you reuse it.
